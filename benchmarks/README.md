# leak_bench - do the guards catch the defects they claim to?

The analogue of PyOD's ADBench for this library's research-integrity guards. It answers one
question with a matrix instead of a list of features: **if a backtest has defect X, which
guard fires?** - and, as a secondary number, how far the reported Sharpe moves because of X.

`RESULTS.md` is regenerated by the script; the method is documented here so the two cannot
drift apart.

## Method

1. **One synthetic world, seeded.** 60 names over 2017-2023 (1,825 trading days), each with
   a persistent latent drift - the single true source of alpha - plus splits, delistings, a
   turbulent regime that covers about a quarter of the sample, a quote feed for as-of joins,
   a fundamentals panel with filing dates and later restatements, and a text score whose
   "model" has a training cutoff inside the sample. Everything the guards look at is present
   in the clean data, so a guard that fires on the clean world is a false alarm.
2. **One simple strategy.** A blend of five sub-signals (trend, a cross-sectional score, the
   text score, a fundamentals signal, a small ML component) run through one pipeline with
   next-bar execution, a stated cost, and an honest reporting window that starts after the
   text model's cutoff. Its net Sharpe on the clean world is the baseline.
3. **A catalogue of defects.** Each takes the clean dataset and returns a corrupted copy plus
   the ground truth of what was done: a look-ahead signal, a wrong-side as-of join, an
   unadjusted split left in the prices, a forward-adjusted (qfq-style) rewrite of history, a
   survivor-only universe, an indicator warm-up leak, a scaler fitted on the full sample and
   shared across CV folds, an unpurged CV split with overlapping labels, restated
   (latest-vintage) fundamentals, a test window overlapping the text model's cutoff, a cost
   assumption ten times too low, and a single calm quarter as the whole test period.
4. **Every guard on every dataset.** The guards are imported from `fin_skills` and called
   through `fin_skills.api` - never copied. Each guard declares its input domain; a defect that
   does not touch that domain is reported as n/a, not a miss, so the matrix does not punish a
   look-ahead check for failing to notice a cost assumption. Recorded per cell: caught (the
   guard's documented failure fired), miss (it ran and stayed silent), false alarm (it fired
   on clean data), runtime.
5. **Effect size.** The strategy is re-run on each corrupted dataset and its net Sharpe is
   compared with the clean baseline. The magnitude is what matters; the sign can go either
   way (an unadjusted split makes the strategy trade fake -50% jumps and lose). The Lo (2002)
   i.i.d. standard error of the Sharpe is printed next to it so that small deltas are read
   as noise.

## How to read the result

The detection matrix is the robust output. Effect sizes are illustrative: each sub-signal is
one fifth of the blend, so a leak in one sub-signal barely moves the blended Sharpe even while
the guard flags it at the source - which is the argument for checking inputs rather than
staring at the final number.

**Gaps are reported, not tuned away.** A guard that ran but whose pass/fail gate did not bind
is listed under GAPS with the numbers, and anything unexpected (a guard firing outside its
domain, a miss) is listed under SURPRISES. As of the current run, one defect is uncaught:
`cost_curve` checks whether the strategy survives at the cost you stated, and a strategy whose
breakeven cost is far above even a ten-times-understated assumption still survives - the gate
is about survival, not about whether the assumption is plausible. A guard for the
plausibility of a cost assumption against traded volume is the next script to write.

## Running it

```bash
python benchmarks/leak_bench.py          # full world, ~20 s, writes benchmarks/RESULTS.md
python benchmarks/leak_bench.py --quick  # smaller world for CI, ~12 s
```

Seeded (`SEED = 20260908`); stdout and `RESULTS.md` are ASCII. Requires only numpy and pandas
plus the installed `fin_skills` package (`pip install -e .` from the repo root).

## Adding a defect or a guard

A defect is a function `Dataset -> Dataset` registered in `DEFECTS` with its severity and the
input domains it touches; a guard is added to `GUARDS` with its domain and the call that runs
it through `fin_skills.api.get(name).run(...)`. Every guard that ships in `fin_skills.api`
should appear here; a guard that cannot be exercised on synthetic data (broker checks, the
QuantLib evaluation-date check) is listed in the script with the reason.
