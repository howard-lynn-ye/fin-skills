\begin{abstract}
Financial research agents must retain relevant information, execute appropriate tools,
and learn from outcomes that were actually available, yet success at one of these steps
does not establish the validity of the final decision.
We present \textsc{fin-skills}, a library for dated financial guidance, executable models
and artifact-bound checks, and examine complementary mechanisms for selective memory:
HiSTrim's protected, sign-preserving context routing and an exploratory fruit-fly-inspired
learner whose delayed feedback is checked before updating memory.
The available financial evidence comprises a \PilotRuns{}-run historical pilot, an audit
feasibility study without independently gradable model submissions, and an autonomous-use
development experiment in which two open-weight models produced 64 valid portfolio
decisions and 43 successful tool calls, without improving mean proxy returns over
no-library controls for either model.
We separately retain the recommendation study's reported HiSTrim comparisons and
distinguish task accuracy, teacher agreement and resource use; these records motivate
testing selective context within financial agents but do not establish a jointly
evaluated system or a general economic benefit.
\end{abstract}

\section{Introduction}
A financial agent can call a forecasting package correctly yet use information that was
unavailable when a trade would have occurred. It can select a familiar algorithm that
does not fit the available data, or report performance from a backtest whose accounting
assumptions differ from the stated trading rule. Access to more tools creates choices;
it does not establish that those choices are appropriate or their outputs valid.

\textsc{fin-skills} addresses these connected problems through a reusable library for
agents working with the Python quantitative-finance ecosystem. Its skills document
library conventions, dated source checks, and failure modes. Executable interfaces let
an agent inspect candidate methods, supply parameters, run supported algorithms, and
receive structured results. Collection interfaces retain information timestamps, while
research checks make missing evidence and detected defects explicit. The library
packages existing methods rather than proposing a new forecasting or trading algorithm.

The agent remains responsible for selecting its tools. A deterministic recommendation
service is available as one tool; it does not replace the model's decision process.
This distinction allows us to compare static guidance, predetermined tool outputs, and
model-selected calls. A separate audit intervention binds check execution to the final
submitted artifact, because stating that a check was performed is not evidence that it
ran on the relevant code and data.

Selective memory raises a related question: what information should remain available
to a decision maker? HiSTrim addresses this within a model's context by retaining
selected historical items while protecting task instructions. The fruit-fly-inspired
component instead updates a persistent learned state from delayed outcomes. Neither
operation validates a financial claim by itself. Our organizing principle is to keep
information selection, execution evidence and feedback validity distinct, and to test
their interaction rather than infer it from separate successes.

This working draft contributes a financial skill and model library, an artifact-bound
audit protocol, and a formulation connecting protected context selection with checked
learning feedback. The library supports direct human use and agent-selected execution;
the two memory mechanisms operate at different stages and have different evidence.
The HiSTrim recommendation study and the financial-agent studies are evaluated
separately. Their combination is a research design, not an already tested controller.

We ask whether final-artifact checks reduce incorrect accepted conclusions, whether
autonomous tool access improves portfolio decisions, and whether checked delayed
feedback can support adaptive learning. The current results support the feasibility
of the LLM portfolio-decision loop. The memory application has implemented components
and identified architectural limitations; its proposed persistence and exit policy
requires further integration. No validated high-return strategy is claimed.

\section{Related work}
CheckList formalizes behavioral testing beyond aggregate task accuracy
\cite{ribeiro2020checklist}. Financial backtest overfitting and selection bias predate
LLM agents \cite{bailey2014deflated,bailey2017pbo}. Profit Mirage investigates information
leakage in financial agents and proposes counterfactual interventions
\cite{li2025profit}. The Finance Agent Benchmark evaluates real financial research tasks
\cite{bigeard2025finance}. FinAgent combines multimodal financial information with
trading tools, reflection, and memory \cite{zhang2024finagent}; StockBench evaluates
sequential portfolio decisions using prices, fundamentals, and news
\cite{chen2025stockbench}. Thus tool-augmented trading, financial-agent leakage, and
counterfactual testing are established research directions. Our focus is a reusable
library and interventions that separate the effects of guidance, tool selection, and
final-artifact checks. The short development study below is not a comparable leaderboard
evaluation against these systems, and its results do not establish superiority.

\label{sec:library}
\paragraph{Knowledge and executable interfaces.}
Domain skills route tasks to relevant libraries, while optional per-library skills
describe conventions, dependencies, and failure modes in more detail. The Python
package exposes catalog search, skill loading, and reference retrieval. Packaged skill
documents and scripts are generated from the same repository sources. A verification
date records a source check; it does not guarantee that a statement remains current.

\paragraph{Algorithm selection and execution.}
The algorithm catalog describes input requirements, optional dependencies, and supported
tasks. Implemented families include portfolio construction, forecasting, volatility and
risk estimation, technical signals, and execution schedules. Recommendation rules filter
candidates by the request and data requirements, then rank compatible entries using
explicit preferences. They are not a learned predictor of future returns. A catalog
entry does not imply that its dependency is installed or that execution will succeed;
unavailable backends and execution failures remain explicit. Automatic execution does
not silently substitute another method after a selected method fails.

\paragraph{Reusable models and lifecycle.}
The library supports direct Python use as well as agent-facing discovery and execution.
Forecasting, regression, and classification adapters expose a common fit--predict
lifecycle, including ARIMA, Ridge, random forests, LightGBM, and XGBoost when their
dependencies are installed. Fitted models can be saved and restored with recorded
environment and input metadata. This loader restores trusted user-created artifacts;
it is not a pretrained-checkpoint download service. Portfolio optimizers and rule-based
signals use execution interfaces without pretending to share a supervised training
lifecycle. The current model registry also exposes an experimental fruit-fly memory
adapter through \texttt{create\_model("fly\_memory")}. Its numerical backend is the
separately installed GPL-3.0-or-later \texttt{fin-skills-fly} extension and requires
caller-supplied circuit parameters. It supports prediction, checked feedback updates
and persistence; it does not implement a complete autonomous trading policy.

\paragraph{Built-in retrieval and model composition.}
The RAG interface chunks packaged skills or caller-supplied documents and retrieves
passages using local BM25. Callers may supply embedding, reranking and text-generation
functions. Passages retain their document identifiers, source offsets and availability
timestamps; as-of retrieval excludes documents unavailable at the requested time.
The index resides in memory and can be persisted as versioned JSON. Citation checks
validate references to retrieved passage labels, not whether a passage supports a claim.

The shared model registry includes a hosted TypeSafe Jev adapter for structured
decisions and passage reranking. It requires service access and explicit network
permission; no Jev weights are distributed with the library. The adapter can serve as
a RAG reranker while a caller-selected model generates the answer. These September 22
additions have interface tests, including mock Jev transports. Live-service inference,
retrieval quality and reranking gains were not evaluated in the earlier studies.
A paired development runner now freezes BM25 candidates, the time cutoff and context
budget before Jev inference, with relevance scoring performed separately on saved
outputs. Its public synthetic fixtures test this workflow. A quality comparison still
requires independently annotated retrieval tasks and an unchanged answering model.

\paragraph{Information availability.}
News collection supports RSS/Atom feeds, static pages, GDELT, and disclosure sources.
SQLite stores collection records, revisions, polling checkpoints and pending alerts;
the operator explicitly starts collection. The package does not ship a populated
financial dataset, and this record store is separate from the RAG index.
Records distinguish publication time from observation time and retain revision
information when available. An as-of digest filters future, stale, and undated records
and deduplicates canonical URLs. These mechanisms support timestamp-aware processing;
they do not reconstruct an independently validated historical news archive. Keyword
risk indicators are not calibrated sentiment estimates, and absent news is treated as
unknown rather than evidence of low risk. News collection is not exercised in the
portfolio experiment reported here.

\paragraph{Model choice and rule-based advice.}
An agent can read a skill, inspect available algorithms, execute a selected method with
its own parameters, and use the returned result in its next decision. The library also
provides an optional market-state adviser based on trailing price and volatility
statistics. Its trend, range, and stress categories are rule outputs, not learned regime
probabilities or validated predictions of which strategy will outperform. A suggested
strategy is therefore additional evidence the model may inspect. The autonomous study
records the model's actual calls; it does not equate access to this adviser with
autonomous algorithm selection.

\paragraph{Research workflow and boundaries.}
Research interfaces support data preflight, candidate evaluation, chronological
validation, holdout reporting, and trial records. Holding final data out of candidate
ranking reduces one avenue for selection bias, but the caller must still provide valid
timestamps and data provenance. Python and JSON tool interfaces expose structured
results; guards requiring live Python objects are not all available as JSON calls.
Neither a data record nor a successful tool call certifies the whole research process.

\section{Audit contract}
Python guards inspect supplied artifacts and return structured findings. The following
receipt mechanism belongs to the experimental audit controller; it is not an automatic
property of every library call.

\paragraph{Audit completeness.}
A task specifies a nonempty set of required guards. A report is \texttt{PASS} only when
all required checks ran and passed with no rejected input; a detected defect yields
\texttt{FAIL}, while missing or rejected checks yield \texttt{INCOMPLETE} in the absence
of a detected failure. Warnings remain visible. A passing subset is not a certificate
that the whole research task is valid.

\paragraph{Execution evidence.}
The controller runs checks on a snapshot of the actual submission and supplied data.
It records each result, elapsed time, and a SHA-256 digest of the code, input files,
manifest and numerical report claims. Changing those artifacts invalidates earlier
receipts. Citation-list changes alone do not invalidate a check. Unknown guard names
and execution errors cannot create successful execution records. Executed-but-failed,
unexecuted, and stale checks are distinct states.

The current intervention binds the library's close-price causality and survivorship
guards to submitted code and positions. It additionally checks reported accounting and
samples same-session dependencies. These checks cover a subset of possible defects.
The runner exposes a fixed guidance excerpt, not the entire skill collection.

\section{Independent evaluation}
A seeded synthetic market provides quoted prices, corporate actions, listings,
post-close commentary, precomputed scores and fundamental disclosures. A submitted
function returns portfolio weights; a separate report states its net Sharpe ratio.
The task now specifies that session-$t$ weights must use information available by the
end of session $t-1$, consistent with close-to-close return accounting.

The independent evaluator redraws future data and individual sessions, measures changes
in submitted positions, checks post-delisting exposure, and recomputes performance at a
fixed transaction-cost convention. Public intervention checks do not call this oracle.
Private grades are generated only after the submission receipt is saved and are not
returned to the agent for repair. Rejected submissions are also graded when executable.

The oracle's fixed-cost Sharpe and the public tool's stated-cost Sharpe answer different
questions. Their discrepancy can reflect accounting conventions as well as coding
errors. Neither should be called an estimate of genuine alpha without timing and other
validity checks. A latent-drift strategy's sample Sharpe is a reference observation,
not a theoretical upper bound. Exceeding it is not mathematical proof of leakage.

\section{Evidence available so far}
\subsection{Synthetic regression checks}
Saved robustness results record \CaughtInstances{} detections among
\DefectInstances{} planted instances: twelve defect families repeated across three
seeded worlds, with no reported clean-control false alarms in those worlds. This is
regression evidence within one synthetic design. Repeating a seed design does not
supply independently authored defects or estimate a general real-world false-positive
rate. The detection suite exercises thirteen guards, not every registered guard.

\subsection{Historical agent pilot}
The saved pilot comprises three markets, two model tiers, and library-present versus
library-absent conditions, with one run per cell. Table~\ref{tab:pilot} recomputes the
mean absolute discrepancy from the saved raw grades. The observed relative reduction

The Haiku library arm has the largest discrepancy in this pilot. This motivates testing
whether guidance, tool use, or other differences explain the outcome. It does not show
that documentation causes weaker models to fail or that mandatory checks solve the
problem. Historical reports of unexecuted guard citations require original execution
logs for verification; the saved grade table alone does not establish that behavior.

\subsection{Numerical and real-data checks}
The numerical benchmark compares implementations with reference calculations using
case-specific tolerances. Passing within tolerance is not exact equality. Runtime
measurements report the names and number of guards actually exercised, skipped and
rejected checks, and machine-dependent timing. A fitted slope across a few data sizes
is descriptive, not an asymptotic complexity bound.

The KOL fixture supports recomputing profile-group aggregates. Its model prediction
metrics are saved summaries, not values independently recomputed from predictions and
outcomes. In particular, its stored pooled Rank IC and mean daily cross-sectional Rank
IC can have different signs. We do not treat this fixture as end-to-end reproduction,
evidence of profitable trading, or external validation of the agent intervention.
A separate evaluator now requires timestamped row-level predictions and outcomes,
reports both forms of IC, and uses paired date-block uncertainty. Those source records
remain an outstanding evidence requirement.

\section{Four-condition study}
The new protocol compares task guidance with ordinary accounting feedback, the same
setup plus a fixed skill excerpt, the excerpt plus optional executable guards, and the
excerpt plus a mandatory final audit. Market data, inference seeds and budgets are
paired. Every condition has the same turn and response-token caps; actual token use,
execution time and tool calls are also recorded. Conditions run in a frozen randomized
order. Failed requests have no hidden retry or synthetic response fallback.

The primary outcome is incorrect accepted submissions divided by all attempted
submissions. Correctness among accepted outputs and overall acceptance rate must be
reported alongside it, so refusing every output cannot appear to solve the task.
Secondary outcomes include independent leakage measures, reporting discrepancy,
post-delisting exposure, unexecuted and stale citations, repair success and resource
cost. Missing, rejected, ungradable and provider-failed runs remain separate outcomes.

The first Beacon run is a public-seed feasibility study using pinned open-weight
models. It tests operation and supports cost and sample-size planning. A confirmatory
study additionally needs independent defect authorship, retained clean cases, repeated
runs, and verified scorer isolation. Market-level paired uncertainty must preserve
repetitions within markets. The present protocol is an amendment after examining the
pilot, not a preregistration of its observations. Failure to find a return difference
would not establish equivalence.

\paragraph{Operational findings.}
The first Beacon preflight rejected valid tool-call JSON wrapped in Markdown fences.
We archived those records and amended the parser before a separate batch; this was
an interface failure, not evidence of financial reasoning failure. In the revised
batch, Qwen2.5-Coder 7B and 14B each completed \BeaconPerModel{} recorded cells, with

\section{Discussion and conclusion}
The studies expose different gaps between a plausible decision and a supported result.
The financial-agent loop demonstrates that models can choose and execute tools, but
successful execution did not improve the primary proxy-return comparison. Audit
receipts make the scope of executed checks explicit, while the feasibility study shows
that artifact validity must be established before financial correctness can be measured.
The recommendation study supplies a concrete context-selection mechanism and reported
task-specific comparisons, with its evidence status recorded in
Appendix~\ref{app:histrim_evidence}. Checked episode feedback addresses a further issue:
whether a learning update uses an outcome available at the time it is consumed.

A joint evaluation should cross context selection with audit access while holding
the backbone, information cutoff, action space and compute budget fixed. Feedback
validation requires a separate matched learning ablation. Such a design can distinguish
context savings, correct execution and adaptation from changes in risk exposure or
available information. The present contribution is a library and a testable account
of these interfaces, supported by separate development studies rather than a claim
that the complete combination improves financial returns.

\section*{Limitations and remaining work}
The Beacon worker uses Linux Landlock and seccomp to restrict filesystem access,
network calls and process creation; unsupported enforcement fails closed. Local
subprocess execution alone provides no such isolation. Submitted Python still shares
an interpreter with individual checks, so host confinement does not establish that
the evaluator resists tampering. A formal adversarial or private-holdout claim needs
an independently protected scorer and additional validation.
Publicly inspected generator code and seeds are development data. Finite perturbations
can miss conditional dependencies; stochastic strategies need repeatability controls.
A passing audit is limited to its input assumptions and required checks. The full
multi-model study and row-level real-world reproduction are not yet established.
The autonomous-use development experiment adds a functioning portfolio-decision loop;
it does not resolve those limitations or establish profitable trading. Its reference-price
data, limited market coverage, unequal actual compute use and previously inspected window
preclude a confirmatory economic-utility claim.
HiSTrim's underlying recommendation run records were not available for this merge;
its retained results are explicitly author-reported. Context compaction can discard
necessary evidence even when protected tokens survive, and the proposed connection
to financial agents has not been evaluated. Resource savings alone do not establish
lower energy use or a better research decision.
