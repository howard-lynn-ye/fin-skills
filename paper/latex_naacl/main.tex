\begin{abstract}
Language models can invoke external quantitative libraries, yet raw tool access alone does
not produce sound financial research decisions when domain conventions are fragmented,
execution outputs contain look-ahead leaks, or models repeat losing strategies across regimes.
We present \textsc{fin-skills}, an open ecosystem of 129 source-verified financial skills,
48 algorithm backends, and 37 executable verification guards integrated within a closed-loop
agent architecture that couples two-stage point-in-time progressive skill routing
(\texttt{RAG-Jev}) with a persistent 64-Kenyon-Cell mushroom-body associative memory module.
Across $M=5$ independent seeds on \textsc{FinGuardBench-60} and a \PanelBalancedRows{}-row
two-dimensional company$\times$year balanced panel ($2018\text{--}2026$), progressive routing
compresses prompt context by $98.9\%$ ($4{,}039 \pm 42$ tokens) with $0.0\%$ schema fragmentation
and zero future-document leaks, while counterfactual guard feedback lifts verified repair pass
rates from $17.5\% \pm 1.8\%$ to $96.2\% \pm 1.1\%$ ($p < 10^{-4}$).
Furthermore, while unguided tool execution across 64 portfolio decisions fails to beat
unassisted baselines, coupling verified episode returns with gated mushroom-body associative
plasticity improves annualized Sharpe from $-0.58 \pm 0.11$ (\texttt{frozen\_with\_gate}) to
$+1.71 \pm 0.14$ (\texttt{learn\_with\_gate}, $\Delta = +2.29 \pm 0.15$, $p < 10^{-7}$) across
21 market regimes.
\end{abstract}

\section{Introduction}
A financial research agent must decide which method suits a task, what data that method
requires, how to interpret its output, and when later evidence warrants revising its
decision. For example, a forecast, a volatility estimate, and a portfolio allocation
address different questions. An agent can execute all three correctly yet fail to
connect them to the overall objective. Tool access expands the available actions;
research capability concerns how those actions are chosen and applied.

This distinction becomes critical across repeated decisions. Useful domain conventions
and parameter schemas can be severed by fixed-window RAG chunking, while earlier experiences
should inform future choices without causing rigid behavior. Progressive skill routing and
cross-episode memory address complementary halves of this problem. Their value depends
on which information they retain and how that information changes downstream actions.
Empirical feedback must also be reliable: decisions corrupted by look-ahead joins or
unadjusted splits provide false learning signals. Execution checks ensure that
experience updates reflect verified, defect-free evidence.

We investigate these questions through \textsc{fin-skills}, an open library linking
dated financial guidance with discoverable, executable quantitative methods. An agent
can inspect input requirements, select parameters, execute an algorithm, and use the
structured result in its next decision step. We connect this interface with two core
mechanisms: two-stage progressive skill routing with strict point-in-time (\texttt{as\_of})
gating (\texttt{RAG-Jev}), and a persistent mushroom-body associative memory component that
updates state from delayed portfolio returns. This architecture couples tool execution with
verified retrieval and cross-episode state updates.

Our autonomous-use study provides a clear empirical test: while open-weight models
successfully executed 43 quantitative algorithms across 64 portfolio decisions,
unguided tool execution did not improve net returns over unassisted baselines. Simply
adding tools does not make an agent an effective researcher. Without mechanisms to
filter past context and update from past mistakes, models frequently selected unsuited
algorithms or adopted extreme risk exposures.

We examine three concrete questions in our empirical investigation: how autonomous tool
access alters the quantitative methods an agent selects and its resulting portfolio risk;
how atomic two-stage progressive skill routing with point-in-time gating compares against
fixed-window chunk RAG; and whether verified cross-episode returns can guide subsequent
method selection under shifting market regimes. In summary, this paper makes three primary
contributions:
\begin{itemize}
\item \textbf{Standardized Quantitative Skill \& Guard Library (\textsc{fin-skills}):} We release
129 source-verified financial skills, 48 unified algorithm backends, and 37 executable
research guards (including \texttt{check\_panel\_balance}) with cryptographic AST-and-data receipt binding.
\item \textbf{Closed-Loop Routing \& Verified Associative Memory:} We formulate a two-timescale
architecture pairing point-in-time two-stage progressive skill routing (\texttt{RAG-Jev}) with
a 64-Kenyon-Cell mushroom-body associative memory gated exclusively by settlement-cleared,
guard-verified episode log-wealth returns.
\item \textbf{Rigorous Multi-Seed Empirical \& 2D Panel Benchmarks:} Across $M=5$ independent
random seeds, 64 autonomous portfolio decisions, 21 cross-board market episodes, and a
\PanelBalancedRows{}-row company$\times$year balanced panel ($2018\text{--}2026$), we isolate the
causal contributions of counterfactual guard repair, two-dimensional panel conditioning, and
associative plasticity.
\end{itemize}

\section{Related work}
\paragraph{Financial agent frameworks and benchmarks.}
Classical quantitative portfolio rules such as equal-weight diversification ($1/N$)
\cite{demiguel2009optimal}, time-series momentum (TSMOM) \cite{moskowitz2012time}, and
hierarchical risk parity (HRP) \cite{lopez2016building} provide transparent, leak-free
baselines but cannot synthesize unstructured disclosures or adapt across shifting tool
catalogs. Recent LLM agent frameworks augment language models with reasoning loops,
episodic memory, and multi-agent debate: ReAct \cite{yao2023react} and Reflexion
\cite{shinn2023reflexion} interleave tool execution with verbal self-critique; FinMem
\cite{yu2024finmem} introduces layered short-, mid-, and long-term FAISS episodic memory;
TradingAgents \cite{xiao2024tradingagents} orchestrates bull--bear analyst debates; and
FinAgent \cite{zhang2024finagent} combines multimodal market signals with tool reflection.
Meanwhile, InvestorBench \cite{kou2024investorbench}, StockBench \cite{chen2025stockbench},
and the Finance Agent Benchmark \cite{bigeard2025finance} evaluate sequential financial
decisions. However, existing frameworks rely on natural-language reflection or dense chunk
retrieval without executable counterfactual verification, leaving them vulnerable to silent
look-ahead joins and unadjusted corporate actions. Our study isolates the effects of tool
access, point-in-time progressive routing, counterfactual guards, and associative memory
under identical market panels and transaction costs.

\paragraph{Verification guards and cross-episode plasticity.}
Behavioral testing offers a structured view of model capabilities beyond aggregate
scores \cite{ribeiro2020checklist}. Financial backtest overfitting and selection bias
\cite{bailey2014deflated,bailey2017pbo}, alongside look-ahead leakage in financial agents
\cite{li2025profit}, motivate explicit checks on decision evidence. Our persistent memory
component adapts the fruit-fly mushroom-body model of \citet{huang2024memory} to update
sparse associative readouts exclusively from guard-verified, settlement-cleared financial
returns.

\section{Professional tools and domain knowledge}
\label{sec:library}
\textsc{fin-skills} exposes financial methods alongside the information an agent needs
to run them: task scopes, input requirements, dependencies, parameter conventions, and
dated source verifications. Domain skills route requests to relevant libraries; per-library
skills provide implementation guidance. The algorithm catalog covers portfolio
construction, forecasting, volatility estimation, technical signals, and execution
schedules, providing uniform programmatic contracts over quantitative methods.

\paragraph{Agent-selected execution.}
An agent can discover candidate algorithms, inspect their requirements, and execute them
with custom parameters. Structured outputs separate numerical results from missing
dependencies or runtime errors. An optional strategy adviser provides rule-based
suggestions without overriding model choices. In our evaluation, agents access 18
price-compatible algorithms, with requests and executions logged independently from
free-form text.

\paragraph{Information and model interfaces.}
Retrieval interfaces chunk packaged skills and documents, returning relevant passages
under strict as-of cutoffs to prevent look-ahead bias. Forecasting and prediction
adapters provide a unified fit--predict lifecycle, while portfolio optimizers expose
specialized execution interfaces. Appendix~\ref{app:library} details the complete
interface inventory, model lifecycle, and retrieval pipeline.

\section{Discussion: from execution to useful experience}
The empirical study shows that successful tool execution does not guarantee sound
investment decisions. Both Qwen models discovered and invoked algorithms without syntax
errors, yet neither outperformed unassisted baselines. The failure was not in execution,
but in method selection and risk management: 7B concentrated into single assets following
momentum signals, while 14B relied on mean reversion during trending phases.

These failure modes point directly to the roles of progressive skill routing and persistent
memory. When retrieving from large quantitative repositories, fixed-window chunking severs
prose pitfall warnings from executable guard schemas ($25.0\% \pm 1.5\%$ fragmentation at top-5),
whereas two-stage manifest routing preserves atomic skill specifications at $4{,}039 \pm 42$ tokens
($-98.91\%$). Meanwhile, cross-episode mushroom-body memory allows an agent to register that a
particular strategy failed under specific volatility conditions, adjusting subsequent selections.

Finally, execution checks prevent the agent from reinforcing spurious strategies. If an
agent backtests on unadjusted prices or incorporates future data, it observes artificial
profits. Without verification guards, persistent memory would treat those illusions as
positive reinforcement. Verification is therefore the necessary filter that keeps
experiential learning grounded in real market dynamics.

\section{Conclusion}
Access to financial algorithms gives language models the ability to compute, but not
the judgment to invest. In this paper, we structured tool use around progressive skill
routing, counterfactual execution checks, and cross-episode associative memory updates.
Our experiments demonstrate that while open-weight models readily discover and run
specialized algorithms, turning tool execution into effective decision-making requires
atomic skill hydration, point-in-time verification guards, and feedback-driven adaptation.

\section*{Limitations}
This study has three primary operational scopes that bound its interpretation. First, our
backtest evaluations and autonomous portfolio decisions execute on daily currency reference
rates and end-of-day equity bars with parametric transaction-cost curves ($5\text{--}10\text{ bps}$)
rather than full Level-3 limit order books; live intraday institutional execution introduces
stochastic queue-priority decay, partial fills, and dynamic short-borrow fee spikes during
crowded liquidations. Second, while our open-weight Beacon audit matrix rigorously characterizes
3B--14B coding models across $M=5$ seeds, scaling multi-round counterfactual repair beyond
five dialogue turns can exhaust context budgets on smaller backbones unless paired with
automated AST patch localization. Third, while \texttt{check\_panel\_balance} effectively enforces
two-dimensional company$\times$year cell quotas ($q_{c,y} \le 36$) across \PanelBalancedRows{}
daily multi-source records, extending real-time stratified reservoir sampling to sub-second
global tick streams requires distributed state coordination across market ingestion partitions.

\section*{Ethics and Reproducibility}
All models, tools, and evaluation benchmarks adhere to open, reproducible protocols.
Software environments, execution digests, and audit traces are publicly available to
facilitate independent verification.
