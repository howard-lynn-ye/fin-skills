\section{Library implementation and interface scope}
\label{app:library}
\paragraph{Knowledge and executable interfaces.}
Domain skills route tasks to relevant libraries, while per-library skills provide
conventions, input schemas, and common failure modes. The Python package exposes
catalog search, skill loading, and reference retrieval. Packaged skill documents and
scripts are compiled from validated repository sources, with all skill entries
documenting primary-source verifications and compatibility metadata.
Table~\ref{tab:inventory} summarizes the core library components.

\paragraph{Algorithm selection and execution.}
The algorithm catalog specifies input requirements, dependencies, and supported tasks.
Implemented families include portfolio construction, forecasting, volatility and risk
estimation, technical signals, and execution schedules. Recommendation rules filter
candidates based on task specifications and input data constraints. The execution layer
avoids silent fallbacks, raising explicit errors when dependencies or data requirements
are not met.

\paragraph{Reusable models and lifecycle.}
The library supports programmatic Python execution as well as agentic tool dispatch.
Forecasting, regression, and classification adapters expose a uniform fit--predict
lifecycle, supporting ARIMA, Ridge, random forests, LightGBM, and XGBoost. Fitted models
and estimators can be serialized and restored alongside environment metadata. The model
registry additionally provides an adapter for the bio-inspired memory architecture via
\texttt{create\_model("fly\_memory")}, supporting prediction, verified feedback updating,
and state serialization.

\paragraph{Built-in retrieval and model composition.}
The RAG interface chunks packaged skills or external documents and retrieves passages
using BM25 and neural rerankers. Passages retain document identifiers, source offsets,
and availability timestamps; point-in-time retrieval excludes documents unavailable at
the requested decision cutoff. Citation checks validate references against retrieved
passage identifiers. The pipeline freezes candidates, temporal cutoffs, and context
budgets prior to neural reranking. On the temporal retrieval benchmark (\texttt{RAG\_JEV\_RESULTS.json}),
point-in-time \texttt{as\_of} filtering records \RAGJevFutureLeaks{} future-document leaks while lifting
\texttt{Recall@3} / \texttt{nDCG@3} from \RAGJevFixedRecall\% / \RAGJevFixedNDCG\% (fixed skill headers)
to \RAGJevDevRecall\% / \RAGJevDevNDCG\% under two-stage BM25 + semantic reranking. Across all $129$ skills
(\RAGIndexedChunks{} chunks) on $60$ evaluation tasks, two-stage progressive manifest routing achieves
$100.0\%$ skill recall with $0.0\%$ code-vs.-guidance fragmentation and $98.3\%$ \texttt{Pass@3} at
$4{,}039$ mean tokens ($-98.9\%$ vs.\ full-library concatenation), compared to $\RAGTopFiveRecall\%$ recall
and $\RAGTopFiveFrag\%$ fragmentation ($75.0\%$ \texttt{Pass@3}) for fixed-chunk BM25 (\texttt{top\_k=5}).

\paragraph{Information availability and point-in-time processing.}
News and disclosure collection supports RSS/Atom feeds, static pages, GDELT, and official
regulatory sources. Collection records distinguish publication time from observation
time and retain revision histories. Point-in-time digests filter future, stale, and
undated records while deduplicating canonical URLs.

\paragraph{Model choice and rule-based advice.}
An agent can inspect skills, discover candidate algorithms, execute chosen methods with
custom parameters, and incorporate numerical outputs into its decision logic.
Market-state categorization provides heuristic regime indicators (trend, range,
stress) that agents can inspect as additional evidence alongside price tables.

\paragraph{Research workflow and audit boundaries.}
Research interfaces enforce chronological validation splits, out-of-sample holdout
reporting, and standardized trial records. Python and JSON tool interfaces return
structured dictionary outputs, ensuring that all intermediate calculations can be logged
and audited.

\paragraph{Local decision and reranking adapters.}
To support reproducible offline auditing without hosted API credentials, \textsc{fin-skills} provides unified local checkpoint adapters spanning pointwise financial encoders (\texttt{ProsusAI/finbert}, \texttt{BAAI/bge-reranker-v2-m3}, and our \texttt{JEV System-One} calibrated router) alongside external negative-control adapters for \texttt{Kev}\footnote{\url{https://github.com/jaredpalmer/kev}} and \texttt{Laya}\footnote{\url{https://github.com/NandhaKishorM/laya}}. All adapters log exact checkpoint hashes, input token budgets, and structured tool receipts, while distinguishing true isotonic probability calibration (Table~\ref{tab:jev_mman_audit}) from uncalibrated heuristic probability normalization.

\paragraph{Three-tier finance-native model matrix vs.\ non-financial negative controls.}
A recurring failure mode in financial agent evaluations is conflating general-purpose routing toys or brittle text parsers with domain-calibrated financial architectures. To isolate model-level and parser-level failure modes, we organize our evaluation around a \textbf{Three-Tier Finance-Native Model Matrix} contrasted against \textbf{Off-the-Shelf Non-Financial and Uncalibrated Negative Controls}:
\begin{itemize}[leftmargin=*,nosep,topsep=2pt]
    \item \textbf{Negative Controls (Off-the-Shelf Non-Financial Rerankers \& Naive Parsers):} We include autoregressive listwise rerankers (\texttt{jaredpalmer/kev-0.8B} and \texttt{kev-4B}), short-context classifiers (\texttt{NandhaKishorM/laya}, 128-token option budget), and unconstrained general/code checkpoints (\texttt{Mistral-Nemo-2407} with regex tokenizer instability and \texttt{Qwen2.5-Coder-14B} coupled to a naive \texttt{json.loads} final-string parser) strictly as negative controls to expose position bias, context truncation, and wrapper-induced parse collapse.
    \item \textbf{Tier 1 (Financial Semantic Routing, Filing Reranking \& Schema-Guided Receipt Verification):} For skill routing and SEC filing evidence retrieval, \textsc{fin-skills} combines fast vectorized lexical search (\texttt{BM25S}) with pointwise financial domain encoders (\texttt{FinBERT}, \texttt{ProsusAI/finbert}; and \texttt{BGE-Reranker-v2-m3}, \citealt{chen2024bgem3}), our \textbf{\texttt{JEV System-One} Calibrated Two-Stage Router}, and \textbf{Schema-Guided Calculator Receipt Verification} (\texttt{Fin-R1} / \texttt{DeepSeek-R1-Distill} program synthesis + \texttt{RAGPipeline} citation gate).
    \item \textbf{Tier 2 (Financial Specialist Agent \& Classical Quantitative Baselines):} In our end-to-end backtest benchmark (Tables~\ref{tab:external_baselines}--\ref{tab:component_ablation}), we compare directly against domain-specific financial agent frameworks---\texttt{FinMem} \citep{yu2024finmem}, \texttt{TradingAgents} \citep{xiao2024tradingagents}, and \texttt{FinAgent} \citep{zhang2024finagent}---as well as classical quantitative allocation baselines---\texttt{HRP} \citep{lopezdeprado2016hrp} and \texttt{TSMOM} \citep{moskowitz2012time}---achieving $96.2\%$ Pass@1, $0.0\%$ survivorship/look-ahead leakage, and $+1.71$ annualized net Sharpe.
    \item \textbf{Tier 3 (Deep Multimodal Network \texttt{MMAN} \& \texttt{JEV System-One} Calibrated Decision on the \CorpusTotalShort{} Corpus):} At the cross-market production scale ($\CorpusTotalRecords$ timestamped records across $\CorpusAnnounceTickers$ A-share and $\CorpusStockTwitsTickers$ US equities; Tables~\ref{tab:panel_balance_latex_naacl}--\ref{tab:jev_mman_audit}), enforcing 2D $(\text{Company} \times \text{Year})$ panel balance ($\PanelBalancedRows$ rows, Year Gini $<0.04$, paired $t=20.14$) enables our \texttt{MMAN} Barra-orthogonal dual-head network to reach out-of-sample Daily Rank IC $= \MMANBarraDualIC$ ($t=11.50$) and our \texttt{JEV System-One} isotonic-calibrated decision gate to achieve a 5-year OOS annualized net Sharpe of $\JEVSharpe$ with $\JEVMaxDDPct\%$ maximum drawdown.
\end{itemize}

\paragraph{Routing permutation invariance and two-stage SEC filing retrieval.}
Part~A of Table~\ref{tab:finqa-rerank-final} evaluates $\RoutingTotalQueries$ skill-routing queries ($36$ skills $\times 3$ query styles) under a seeded shuffled candidate order and its exact reversal. Because \texttt{Kev-0.8B} and \texttt{Kev-4B} score all candidates jointly inside an autoregressive prompt, reversing candidate order flips their Top-1 decision on $\RoutingKevZeroEightFlips/\RoutingTotalQueries$ ($\RoutingKevZeroEightFlipPct\%$) and $\RoutingKevFourBFlips/\RoutingTotalQueries$ ($\RoutingKevFourBFlipPct\%$) of queries, respectively, while \texttt{Laya} rejects all $\RoutingLayaRejections/\RoutingTotalQueries$ queries prior to inference because full skill specifications exceed its 128-token per-option budget. In contrast, pointwise scoring with \texttt{BM25S} ($\RoutingBMTwoFiveTopOne/\RoutingTotalQueries$), \texttt{FinBERT} ($\RoutingFinBERTTopOne/\RoutingTotalQueries$), and \texttt{BGE-Reranker-v2-m3} ($\RoutingBGERerankerTopOne/\RoutingTotalQueries$) guarantees exact permutation invariance ($0/\RoutingTotalQueries$ flips), and our \texttt{JEV System-One} calibrated two-stage router lifts Top-1 accuracy to $\RoutingJEVCalibratedTopOne/\RoutingTotalQueries$ ($\RoutingJEVCalibratedTopOnePct\%$) and Recall@3 to $\RoutingJEVCalibratedRecallThree/\RoutingTotalQueries$ ($\RoutingJEVCalibratedRecallThreePct\%$) with zero order flips. To test whether two-stage reranking transfers to long-form corporate filings, we also indexed $\FinBenchNonemptyPages$ nonempty pages across $\FinBenchExtractedPDFs$ local SEC PDFs for the $\FinBenchQuestions$-question FinanceBench benchmark \citep{islam2023financebench}. Vectorizing lexical retrieval with \texttt{BM25S} reduces median query latency from $5.504$\,s to $\FinBenchBMTwoFiveSLatencySec$\,s ($0.125$\,s index build), while adding second-stage \texttt{BGE} cross-encoder reranking over the top-25 lexical pages improves Top-1 evidence-page hit rate by $\FinBenchTopOneRelGainPct\%$ ($\FinBenchBMTwoFiveTopOne/\FinBenchQuestions \rightarrow \FinBenchBMTwoFiveBGETopOne/\FinBenchQuestions$) and Top-5 hit rate by $\FinBenchTopFiveRelGainPct\%$ ($\FinBenchBMTwoFiveTopFive/\FinBenchQuestions \rightarrow \FinBenchBMTwoFiveBGETopFive/\FinBenchQuestions$).

\paragraph{FinQA receipt verification, citation gating, and flat tool-catalog guidance.}
Part~B of Table~\ref{tab:finqa-rerank-final} resolves an instructive evaluation pathology on $\FinQATotalQuestions$ FinQA numerical reasoning questions \citep{chen2021finqa}. Under the legacy unconstrained harness, pairing \texttt{Mistral-Nemo-2407} or \texttt{Qwen2.5-Coder-14B} with a naive \texttt{json.loads} parser produced $0/\FinQATotalQuestions$ and $\FinQAQwenBGENaiveCorrect/\FinQATotalQuestions$ correct completions. Trajectory forensics revealed that in $\FinQAVerifiedCalcRuns/\FinQATotalQuestions$ ($\FinQAVerifiedCalcPct\%$) of runs, the agent \emph{did} execute valid intermediate \texttt{calculator} tool calls, but naive final-string parsing threw \texttt{JSONDecodeError} whenever the model wrapped its final JSON in Markdown \texttt{`{}`{}`{}json} fences ($\FinQAQwenBGEFenceErrors/\FinQATotalQuestions$ runs on Qwen; $7/\FinQATotalQuestions$ on Mistral) or hit the 8-turn LlamaIndex limit ($23/\FinQATotalQuestions$ on Mistral). Replacing naive string parsing with \textbf{Schema-Guided Receipt Recovery} recovers $\FinQAQwenSchemaReceiptCorrect/\FinQATotalQuestions$ ($\FinQAQwenSchemaReceiptPct\%$) verified answers on \texttt{Qwen2.5-Coder-14B} with $0/\FinQATotalQuestions$ parse errors, while our \textbf{\texttt{JEV} Two-Stage Reranker + \texttt{Fin-R1} Calculator Gate} achieves $\FinQAJEVFinROneCalcCorrect/\FinQATotalQuestions$ ($\FinQAJEVFinROneCalcPct\%$) gold-evidence recall and verified execution accuracy. Simultaneously, enforcing the \texttt{RAGPipeline} \textbf{Citation Gate}---which rejects any numerical claim lacking a verified calculator receipt and retrieved chunk ID---reduces \texttt{Incorrect Accepted} FinQA answers from $5/\FinQATotalQuestions$ down to $\mathbf{0/\FinQATotalQuestions}$. Across a 15-tool LlamaIndex catalog ablation comparing \texttt{Generic} (one-line descriptions), \texttt{Organized} (nested category headers), and \texttt{Flat guidance} (concise inline operational rules), \textbf{\texttt{Flat guidance}} achieves the highest verified completion ($\FrameworkFlatQwenCorrect/\FinQATotalQuestions = \FrameworkFlatQwenPct\%$ on Qwen with $0$ format errors and $0$ call-limit exceptions, vs.\ $\FrameworkOrgQwenCorrect/\FinQATotalQuestions$ Organized and $\FrameworkGenQwenCorrect/\FinQATotalQuestions$ Generic; and $\FrameworkFlatMistralCorrect/\FinQATotalQuestions$ vs.\ $\FrameworkOrgMistralCorrect/\FinQATotalQuestions$ on Mistral), demonstrating that flat, decision-oriented inline rules outperform deep tool hierarchies.

\paragraph{Storage crash recovery and arrival-order vs.\ point-in-time revision semantics.}
Finally, we audited the SQLite collection and monitoring state store across four process-termination boundaries (\texttt{before\_save}, \texttt{mid\_batch}, \texttt{pre\_commit}, and \texttt{post\_commit}, three repeats each = $\SQLiteSigkillRecovery$ \texttt{SIGKILL} injections) and scale runs of $100$, $1{,}000$, and $10{,}000$ synthetic events ($0.154$\,s / $0.404$\,s / $3.036$\,s ingest; $45.8$\,ms / $56.6$\,ms / $58.1$\,ms reopen; $3.89$\,ms / $4.54$\,ms / $8.67$\,ms median latest-query latency). All $\SQLiteSigkillRecovery$ crash tests recovered the exact atomic database state across event records, latest-version pointers, pending alerts, and collection cursors. Crucially, an out-of-order revision injection test confirmed a vital architectural boundary: the storage engine's operational \texttt{latest} pointer tracks \emph{arrival order} rather than chronological publication order, so a delayed restatement or backfilled historical revision arriving last becomes the current operational record. Consequently, historical backtests must never treat storage arrival pointers as point-in-time knowledge, motivating our mandatory \texttt{check\_pit\_fundamentals} and \texttt{check\_safe\_asof} runtime guards.
